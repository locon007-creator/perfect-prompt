# Minimal Engine v1 Design

## Goal
Replace Perfect Prompt's heavy compiler-first generation path with a predictable minimalist engine that preserves the user's raw idea, applies only a small set of hard builder guardrails, and lets Gemini perform semantic reasoning and final prompt writing without inheriting parser damage.

## Non-goals
- No visual/UI redesign.
- No new screens or settings.
- No project-specific hardcoding for Finance, Drop & Hook, Timesheet, or any one product.
- No removal of Gemini fallback behavior.

## Source-of-truth order
1. Raw user idea is highest authority for purpose, workflow, features, conditions, timing, exclusions, and behavior.
2. Hard creation-format guardrails apply to app/web-app generation. Perfect Prompt's default app output is one self-contained `index.html` with inline CSS and JavaScript, no React/framework/build step/extra files, mobile portrait 360–430 px unless the raw idea explicitly requests a different stack.
3. Selected visual style may influence presentation language but cannot change the stack, workflow, or product logic.
4. Gemini may reorganize and clarify the prompt but cannot omit or contradict the raw idea or hard guardrails.

## Architecture
Generation becomes:

`raw idea -> Minimal Engine deterministic wrapper -> Gemini reasoning/final writing -> lightweight validator -> final prompt`

The old parser/compiler remains in the repository temporarily for regression reference and rollback, but the Generate flow no longer depends on its parsed feature extraction for app/web-app prompts.

### Minimal Engine
A new focused module builds a deterministic wrapper with only:
- Role
- Creation Format
- Product Brief containing the raw idea essentially verbatim
- Execution Rules
- Visual Direction from the selected style when available
- Deliverable

It does not infer screens, rewrite workflows, extract fragments, manufacture settings, or create product-specific features.

### Gemini pass
The API receives the raw idea plus Minimal Engine wrapper. Gemini is instructed to reason from the raw idea first, preserve all requirements, keep HTML hard locks intact, remove contradictions, and output one copy-ready builder prompt only.

### Validator
A lightweight post-generation validator checks hard invariants for app/web-app output:
- references `index.html`
- requires inline CSS and JavaScript
- forbids React/framework/build-step/extra-file drift
- retains 360–430 px portrait/mobile constraint
- never accepts native iOS/Android creation-format text when HTML is locked

If the AI result violates these invariants, the client keeps the deterministic Minimal Engine prompt rather than surfacing a contradictory AI result.

## Compatibility
Existing UI controls, saved preferences, copy/save/clear behavior, and visual layout stay unchanged. Other build types can continue using the current routing until migrated deliberately.

## Testing
Use TDD with regression tests covering:
1. A complex financial brief survives verbatim enough that fixed/variable logic, reminder timing, card-paid bill assignment, and double-count prevention remain present.
2. App/web-app output is always HTML-locked even if the selector says iOS or Android.
3. No broken parser fragments such as `1. Every setup` or `Paid.` are generated by the Minimal Engine.
4. AI result validation rejects stack contradictions.
5. Existing UI and request integration tests continue passing.

## Success criteria
- Same complex input produces a coherent copy-ready prompt without dropped logic or stack contradiction.
- HTML is the default enforced app build format.
- Gemini failure still leaves a useful deterministic prompt.
- No visual changes.
- Full test, typecheck, build, and eval suites pass before merge.
